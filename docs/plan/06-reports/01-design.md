# 設計

`03-decisions.md` の推奨案を前提に書いている。回答で変わったところは実装前にここを直す。

## 1. レポートの期間と公開日

| 種類 | 期間 | 公開日 | 見出しの例 |
| --- | --- | --- | --- |
| 月半ば | その月の1日〜15日 | 15日 | 11月前半のレポート(11月1日〜15日) |
| 月末 | その月の1日〜月末(28〜31日) | 月末の日 | 11月のレポート(11月1日〜30日) |

- 公開日はデザイン(ホームの「次のレポート 10月31日(土)月末のレポート」)に合わせて期間の最終日にする(03-decisions.md #1)。
  公開日は朝の測定のあとに開くことが多いので、最終日の記録も入る。入っていなくても、開くたびに取り直して作り直す。
- 期間の始まりは計画の開始日より前にしない。開始日より前に終わる期間は作らない。
  - 例: 開始日 2026-10-24 → 最初のレポートは「10月のレポート(10月24日〜31日)」。10月の月半ばは作らない。
  - 開始日が1〜15日なら、その月の月半ばは「開始日〜15日」。
- 日付はすべて `AppCalendar.tokyo`(Asia/Tokyo)の `CalendarDay` で扱う。月末の日は暦から求める(2月、うるう年)。
- `ReportPeriod.released(startDay:through:)` は、公開日が `today` 以下の期間を古い順に返す。`next(after:)` は次の公開日の期間を返す。

## 2. レポートは保存せず、開くたびに作る(03-decisions.md #2)

- 体重・体脂肪率は HealthKit から取り直し、計画の状態は保存した履歴(4.)から引いて、毎回同じ規則で計算する。
- そのため後から届いた記録(HealthPlanet の同期が遅れた日)も反映される。過去のレポートの数字が後から変わることはありうるが、元のデータが変わったときだけ。
- 取得範囲は今と同じ(計画の開始日の6日前から今日まで)。最初の期間の比較の基準は開始時(3.)なので、範囲を広げる必要はない。

## 3. 集計の規則

### 記録できた日

- 期間内で体重の記録(1日の値)がある日の数 / 期間の日数。日ごとの有無も持つ(デザインの四角の並び)。
- 体脂肪率だけの日は数えない。

### 体重の流れ

| 項目 | 規則 |
| --- | --- |
| 期間の値 | 期間の最終日に終わる7日平均(0.1kg に丸める)。出なければ「記録が少なく、平均を出せませんでした」 |
| 比較の基準 | 前の月の末日に終わる7日平均。前の月の末日が計画の開始日より前なら、計画の開始体重(`roadmap.startWeight`)で「開始時」と表示する。7日平均が出なければ基準を出さない |
| 月末の差 | 期間の値 − 基準(0.1kg)。「10月末 122.7 kg から −3.4 kg」 |

月半ばも基準は前の月の末日(デザインの「122.7 → 121.4」)。月半ばの基準を「前の月の15日」にしない。

### 目安と進み具合(期間の最終日のフェーズで判定)

- 期間の最終日のフェーズを履歴(4.)から引き、そのフェーズで判定する。
  - 減量中: 目安 = `Guideline.expectedWeight(phase:on:)`、進み具合 = `ProgressJudgment.judge(...)`。最初の1か月は `settlingIn`。
  - 維持期間・維持モード: 目安の代わりに「維持の範囲」(到達時体重 ±2%、kg で表示)と、範囲に収まっているか(収まっている / 少し上 / 少し下)を言葉で出す。
- 期間の途中でフェーズが変わったとき(到達・卒業・見直しの採用)は、「この期間の出来事」として日付と一言を添える(履歴から作る)。
- 7日平均が出なければ進み具合は出さない。

### 体組成(03-decisions.md #3、#4)

| 項目 | 規則 |
| --- | --- |
| 1日の除脂肪量 | 同じ日に体重と体脂肪率の両方がある日だけ、体重 × (1 − 体脂肪率)。体重・体脂肪率とも1日の値(HealthPlanet 優先、最初の測定)を使う |
| 代表値 | 期間の最終日に終わる7日間にある値の平均(体脂肪率と除脂肪量を別々に)。1件でもあれば出す(7日平均と同じ) |
| 比較の基準 | 前の月の末日に終わる7日間の平均。前の月の末日が計画の開始日より前なら、計画の開始日に終わる7日間 |
| 変化の方向 | 差を表示の単位(体脂肪率 0.1ポイント、除脂肪量 0.1kg)に丸めてから比べる。体脂肪率 ±0.5ポイント以内、除脂肪量 ±0.5kg 以内は「横ばい」(境界ちょうどは横ばい)。それを超えて下がれば「下がった」、上がれば「上がった」 |
| 出せないとき | 期間か基準のどちらかの代表値が出なければ、方向も数値も出さず「体脂肪率の記録が少なく、比べられませんでした」 |
| 月半ば | 方向だけ。数値は型の段階で持たない(5. の `ReportContent`) |
| 月末 | 基準と期間の数値(体脂肪率 %、除脂肪量 kg、小数第1位)と方向。基準の列の見出しは「10月」(前の月)または「開始時」 |
| 一言(月末) | 除脂肪量が下がったとき「体重が減ると、除脂肪量も少し減るのは自然なことです。」。体重が減り、減った体重のうち脂肪量(体重 × 体脂肪率)の減少が半分以上なら「減った体重の半分以上は脂肪でした。」を続ける |

### ステージ

- 期間の最終日のフェーズのステージ番号(体重から逆算しない)。維持モードなら「維持モード」。
- 月半ば: ステージ番号と進み具合の一言だけ(デザインの「ステージ1 / 計画どおりに進んでいます」)。
- 月末: ホームのステージカードと同じ形(次の区切り、起点、進み具合のバー、到達予定)。到達予定は今の計画の値だけを出す(矢印で前後を並べない。03-decisions.md #5)。
- 過去のレポートでは、ステージの表示は期間の最終日のフェーズ、到達予定は出さない(当時の予定は保存していないため)。

### 実績ペースの一言(月末だけ、03-decisions.md #6)

- 期間の最終日に終わる `ActualPace`(減量中だけ、窓の規則は今と同じ)。
- 月3%を超えたとき: ホームの速すぎるペースと同じ趣旨の一言。
- 月3%以内で、進み具合が「予定より早いペース」のとき: 数値を出さずに「目標ペースはそのままに、前倒しとして見守ります」の一言。
- それ以外は出さない。ペースの割合(「月2.8%」)は出さない。

### 計画見直しの提案(03-decisions.md #7)

- 最新のレポートを開いているときに、ホームで計画見直しのカードが出る条件(今日の `shouldProposePlanReview`)が成り立っていれば、同じ提案カードをレポートの最後に出す。押したときの操作もホームと同じ(`HomeModel` の採用 / 断る)。
- 過去のレポートには出さない。

## 4. フェーズの履歴(過去のレポートの目安とステージに使う)

- WeightCore に `PhaseTimeline` を置く: `entries: [(from: CalendarDay, phase: PlanPhase)]`(古い順)、`phase(on:)` は `from <= day` の最後の項目。最初の項目より前は nil。
- `PlanRecord.phaseHistory: [PhaseTimeline.Entry]?` を足す(省略可能、`schemaVersion` は 1 のまま)。
- 追記する操作と `from` の日:

| 操作 | from |
| --- | --- |
| 自動遷移(到達・卒業、`apply(_:)`) | 各ステップの日(到達日、卒業日) |
| 85日目の「次のステージへ進む」 | 押した日 |
| 早期到達の採用 | 押した日 |
| 計画見直しの採用 | 押した日(新しい起点の日) |
| 元の計画に戻す | 押した日(この日から元のフェーズに従う。採用していた間は見直した計画で判定する) |

- 同じ日に2回変わったら、その日の項目は後のもので置き換える。
- 初回設定で作るときは `[(開始日, .losing(1, origin: 開始))]` を入れる。
- 履歴のない既存の plan.json は、`[(開始日, .losing(1, (開始体重, 開始日)))]` に、今のフェーズが違えば `(今のフェーズの起点の日, 今のフェーズ)` を足したものとして読む(読み込み時の補完で、ファイルは書き換えない。次にフェーズが変わったときに保存される)。
  今の実運用の計画(2026-10-24 開始、ステージ1の減量中)はこれで正確に再現できる。

## 5. 表示用のモデル

`ReportBuilder`(アプリ、純粋)が、取得済みの1日の体重・体脂肪率、`PlanRecord`、`today` から作る。

```swift
struct ReportContent: Equatable, Identifiable {
    var period: ReportPeriod          // 種類、年月、期間(開始日で切った範囲)、公開日
    var continuity: RecordContinuity  // 記録できた日、日ごとの有無
    var weight: WeightFlow            // 基準(前月末 / 開始時)、期間の値、月末の差
    var plan: PlanSection?            // 目安・進み具合 または 維持の範囲、ステージ、期間内の出来事
    var composition: CompositionSection
    var paceNote: PaceNote?           // 月末だけ
    var isLatest: Bool
}

enum CompositionSection: Equatable {
    case unavailable
    /// 月半ば。方向だけで、数値は持たない。
    case directions(fat: CompositionDirection, lean: CompositionDirection)
    /// 月末。数値と方向。
    case values(baselineLabel: BaselineLabel, fat: CompositionValues, lean: CompositionValues, note: CompositionNote?)
}
```

- `DailySummary` に `reports: [ReportContent]`(公開済み、古い順)と `nextReport: ReportPeriod?` を足す。`DailySummaryBuilder` の取得のあと、判定と同じ流れで作る。
- 既読: 最後に開いたレポートの ID(例 `2026-11-mid`)を `UserDefaults`(標準)に保存する。計画のデータではなく、ウィジェットも使わないので plan.json に入れない(03-decisions.md #8)。

## 6. 画面

| 画面 | 内容 |
| --- | --- |
| レポートタブ | 最新のレポートを表示。上部に「前のレポート」「次のレポート」の移動(古い順の一覧の中で)。公開済みがなければ「最初のレポートは {日付} に届きます」 |
| 月半ば | 記録できた日(n日 / m日、四角の並び、一言)→ 体重の流れ(基準 → 値、目安と実際、進み具合の言葉)→ 体組成の変化(方向、「数値は {月末の日} の月末レポートでお届けします」)→ ステージと進み具合 →(最新なら)見直しの提案 |
| 月末 | 記録できた日と体重(7日平均、基準からの差)、月末の目安と進み具合 → 体組成(基準と今月の数値、一言)→ ステージ(区切り、バー、到達予定)→ ペースの一言 →(最新なら)見直しの提案 |
| ホーム | 一番下に「次のレポート」カード。未読の公開済みがあれば「{見出し}が届きました」、なければ「次のレポート {日付} {種類}」。押すとレポートタブへ移る(`TabView` の選択を `MainTabView` で持つ) |

- 色はフェーズ5までと同じ(アクセントの緑と灰色)。方向の矢印(↓ → ↑)は灰色と緑だけで、赤や警告色は使わない。「上がった」も同じ色。
- 体組成の数値を出すのは月末のレポートだけ。ホーム・ロードマップ・月半ばには出さない。

## 7. 型と責務

| 型 | 場所 | 責務 |
| --- | --- | --- |
| `ReportPeriod` | WeightCore | 期間、公開日、公開済みの一覧、次の期間 |
| `RecordContinuity` | WeightCore | 記録できた日の集計 |
| `BodyComposition` / `CompositionDirection` | WeightCore | 除脂肪量の計算、代表値、方向の判定 |
| `WeightReport` | WeightCore | 体重の流れ(基準、値、差)と目安・進み具合・維持の範囲の判定(既存の判定を呼ぶ) |
| `PhaseTimeline` | WeightCore | 日付からフェーズを引く |
| `ReportSettings` | WeightCore | 月半ばの最終日(15)、体組成の横ばいの幅、脂肪の割合の一言の閾値(0.5)。plan.json に保存しない(`PlanSettings` に足すと既存のファイルが読めなくなるため) |
| `PlanRecord.phaseHistory` と追記 | アプリ(Data) | 4. の表 |
| `ReportBuilder` / `ReportContent` | アプリ(App) | 表示用のモデル。文言は持たず、種類と値だけ |
| `ReportView` ほか | アプリ(Views) | 表示と文言 |
