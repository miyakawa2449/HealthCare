# 決めていただきたいこと

状態: **回答済み・承認済み**(2026-11-24、すべて推奨どおり)

推奨案のままでよければ「推奨どおり」と書いてください。

### 1. レポートが届く日

- 推奨案: 期間の最終日(15日と月末の日)。デザインのホーム「次のレポート 10月31日(土)月末のレポート」に合わせる。最終日の記録がまだなくても、開くたびに作り直すので、記録が入れば反映される。
- 代替案: 期間が終わった翌日(16日と翌月1日)。最終日の記録が必ず入った状態で届く。
- 回答: 推奨どおり。

### 2. レポートを保存するか

- 推奨案: 保存しない。開くたびに HealthKit の記録と、保存したフェーズの履歴から作り直す。後から届いた記録も入り、アプリを開かなかった月のレポートも作れる。
- 代替案: 初めて開いたときの内容を保存して固定する(後から記録が届いても変わらない。開かなかった月のレポートはない)。
- 回答: 推奨どおり。

### 3. 体組成の「横ばい」の幅

- 推奨案: 体脂肪率は ±0.5ポイント以内、除脂肪量は ±0.5kg 以内を「横ばい」(境界ちょうどは横ばい)。体組成計の体脂肪率は日によって1ポイント前後揺れるので、小さな上下を「上がった」と出さないため。値は `ReportSettings` に置き、後で変えられる。
- 代替案: 表示の単位(0.1)で同じなら横ばい(少しでも動けば方向が出る)。または体脂肪率 ±1.0ポイント / 除脂肪量 ±1.0kg。
- 回答: 推奨どおり。

### 4. 体組成の代表値と比較の基準

- 推奨案: 期間の最終日に終わる7日間の平均(体重の7日平均と同じ考え方)。基準は前の月の末日に終わる7日間。月半ばも月末も、前の月の末日と比べる。最初の月だけは計画の開始日に終わる7日間と比べ、列の見出しを「開始時」にする。
- 代替案: 期間全体の平均同士を比べる(月半ばなら 1〜15日の平均と前月の平均)。
- 回答: 推奨どおり。

### 5. 月末レポートの到達予定に矢印(「1月上旬 → 12月中旬」)を出すか

- 推奨案: 出さない。今の計画の到達予定だけを出す。今の到達予定は計画(月2%)から計算していて、実際のペースでは動かない(動くのは到達・卒業・見直しの採用のときだけ)ので、毎月の前後比較にしても多くの月で同じ値になる。
- 代替案: 前の月末時点の到達予定を保存しておき、変わった月だけ「前 → 今」を出す。
- 回答: 推奨どおり。

### 6. 月末レポートのペースの一言(デザインの「今月は月2.8%のペースでした。3%以内なので…」)

AGENTS.md では「実績ペースについて伝えるのは月3%を超えたときだけ」、デザインでは月2.8%のときも割合を出している。

- 推奨案: 割合の数値は出さない。月3%を超えたときはホームと同じ趣旨の一言(ペースを落としてよい)。3%以内で進み具合が「予定より早いペース」のときだけ、「目標ペースはそのままに、前倒しとして見守ります」と数値なしで添える。それ以外は出さない。
- 代替案A: デザインどおり、月末では割合(月n%)と一言を出す。
- 代替案B: AGENTS.md どおり、3%を超えたときだけ出す(前倒しの一言も出さない)。
- 回答: 推奨どおり。

### 7. レポートでの計画見直しの提案

- 推奨案: 最新のレポートを開いたとき、今日ホームで見直しのカードが出る条件なら、同じカードをレポートの最後にも出す(押したときの動きもホームと同じ)。過去のレポートには出さない。
- 理由: concept.md の「次にアプリを開いたときのカード表示か、月半ば・月末レポートの中で伝える」を満たし、判定を2つに分けない。
- 代替案: レポートでは「ホームに計画の見直しの提案があります」の一言だけ。
- 回答: 推奨どおり。

### 8. 「届きました」のための既読の保存先

- 推奨案: 最後に開いたレポートの ID を `UserDefaults`(標準)に保存する。計画のデータではなく、ウィジェットも使わないので plan.json に入れない。
- 代替案: `PlanRecord` に省略可能な項目として足す。
- 回答: 推奨どおり。

### 9. フェーズの履歴を保存する

- 推奨案: `PlanRecord.phaseHistory` を足して、過去のレポートの目安とステージを当時のフェーズで出す(01-design.md 4.)。履歴のない今の plan.json は、開始時と今のフェーズから補完する(今の計画は正確に再現できる)。
- 代替案: 履歴を持たず、過去のレポートも今のフェーズで目安を計算する(ステージが進むと過去のレポートの目安が変わってしまう)。
- 回答: 推奨どおり。

### 10. 「計画を作り直す」の入口

フェーズ5のときに「フェーズ6で検討」としていたもの。

- 推奨案: このフェーズでは作らず、フェーズ8(仕上げ)に回す。レポートとは独立していて、作り直したときの履歴とレポートの扱い(過去のレポートを残すか)を別に決める必要があるため。
- 代替案: このフェーズでロードマップ画面の下に入口を置く(作り直すと履歴とレポートは新しい計画の開始日から)。
- 回答: 推奨どおり。

- 回答: 最初の1か月も体組成(方向と、月末の数値)を出す。今の実装のままで、変更しない。
