フェーズ4以降は画面と文言を実機で見て直す往復が入るため、1フェーズあたりの時間は長くなる見込み。

## 期間の目安

- 全体で 6〜9セッション。1日の作業時間が2時間か4時間かで大きく変わるので、週や日数での見積もりは各フェーズの計画時に更新する。
- レポート(フェーズ6)は実データが月末まで溜まらないため、開発はモックのデータで進め、本当の確認は運用の中で行う。
- ウィジェットと受信(フェーズ7)は実機でしか確認できず、HealthPlanet の同期後に届くかは数日の経過観察が要る。

## フェーズの分け方の考え方

- 4 と 5 は1つにまとめることもできるが、「ホーム画面の見た目と文言の確定」と「カードの状態遷移と選択の保存」は確認の仕方が違う(前者は実機で見る、後者はテストで固める)ので分けた。
- 「後のフェーズで扱う要素」(AGENTS.md)の 1 と 2 はそれぞれ 5 と 8 に入れた。3 と 4 は 8。
- 各フェーズの計画は `docs/plan/0N-<name>/` に README・設計・テスト項目・決定事項の形で置き、人間の承認後に実装する(CLAUDE.md の進め方)。
