# 体重管理アプリ コンセプトシート

Oct 18, 2026 · @Tsuyoshi Miyakawa

## 背景と課題

続かなかった原因はデータ不足ではなく、毎回すべての数値と評価を見せられることにある。

- 以前は半年で20kg減らせたが、その後続かなくなりリバウンドした。
- 体重計アプリ(タニタ HealthPlanet)は、測るたびに体脂肪率・筋肉量・内臓脂肪・体内年齢と「肥満」「過剰」などの評価を表示する。これが気になり、記録をやめてしまうことが続いた。
- 最終目標(BMI22の標準体重)までは約56kgあり、遠すぎて意欲を保ちにくい。

| 項目 | 2026年10月18日時点 |
| --- | --- |
| 身長 | 175cm |
| 体重 | 123.5kg |
| BMI | 40.3 |
| 最終目標 | 67.4kg(BMI22) |

## コンセプト:見せすぎない体重計

毎日は体重だけを静かに記録し、それ以外はアプリが裏で見守る。減った量より、続いたことと維持できたことを成果にする。

1. **毎日は体重だけ。** 体組成データは日々の画面に出さない。
2. **体組成は月2回のレポートで。** 裏で蓄積し、月半ばと月末のレポートとして届ける。
3. **評価ラベルを使わない。** 「肥満」「過剰」「低い」は表示しない。責めない言葉づかいにする。
4. **遠いゴールを見せない。** 最終目標はロードマップ画面にだけ置き、普段は今のステージだけを示す。
5. **続いたことを成果にする。** 連続記録が途切れても罰を与えない。維持期間も成果として扱う。

対象ユーザーは自分ひとり(個人用アプリ)。

## 画面と表示ルール

メイン画面に出す数値は体重だけで、主役は日々の揺れを均した7日平均にする。

| 画面 | 表示するもの | 表示しないもの |
| --- | --- | --- |
| メイン(毎日) | 7日平均体重(大)と計画の点線、当日の体重(小)、今のステージと進み具合、記録カレンダー | 体組成、BMI、最終目標(最終ステージでは「次の区切り」として出す)、評価ラベル |
| 月半ば・月末レポート | 体重の目安と実際の値、進み具合の判定、体脂肪率・除脂肪量の変化の方向(下がった/横ばい/上がった)、記録の継続、計画の見直し提案。月末のレポートのみ体組成の数値も表示 | 月半ばのレポートでは体組成の数値 |
| ロードマップ | 全ステージ、最終目標、到達予定日、安全性の判定 | 評価ラベル |
| ウィジェット | 7日平均体重、今のステージ | 体組成 |

**レポートの周期**

- 月半ばレポートは1日〜15日、月末レポートは1日〜月末(月全体)を対象にする。
- 計画見直しの発動条件にある「2週間」は14日の窓で、レポートの周期とは別に扱う。

**1日1回の値のルール**

- 1日に複数回測った場合は、その日の最初の測定値を採用する。
- 朝と夕方で1kg以上変わることがあるため、測る時間帯を揃えるよう案内する。

**言葉づかい**

- 「遅れています」「増えました」ではなく、事実を穏やかに伝える。
- 例:「最近のペースに合わせて、計画を少しゆるめました」
- トロフィーやカレンダーでの可視化は、読書継続支援アプリの仕組みを流用する。

## ロードマップ機能

最終目標67.4kgまでを、ステージと維持期間に分けて計画する。各ステージは、そのステージ開始時の体重から10%減った体重を次の境界にする(最後のステージは最終目標で打ち切る)。無理のないペースなら約3年4か月の計画になる。

### 開始体重と開始日

- 開始日は初回設定で選ぶ(初期値は設定した日。HealthKitにある最初の記録の日から今日までを選べる)。開始体重は、開始日に終わる7日平均(窓に記録がない場合はその日までの最新値)を初期値として示し、ユーザーが確認・修正する。
- 計画の見直しを採用したときは、その時点の7日平均と日付を新しい起点にして、ペースと到達予定日を計算し直す。ステージの境界は変えない。元の計画は「元の計画に戻す」のために保持する。

### 2つのモード

- **自動作成モード:** 最終目標を入れると、無理のないペースで計画を作る。
- **期日指定モード:** 目標日を入れると必要なペースを逆算し、安全性を判定する。危険な場合は「この期日なら、ここまでが安全」という代替案を示す。

### 安全性の判定基準

減量ペースは、その時点の7日平均に対する1週間あたりの割合で判定する。体重が減るほど、許容されるkgも自然に小さくなる。この判定は計画を立てるとき(期日指定モードで必要なペースを評価するとき)の基準として使う。

| 判定 | ペース | 123.5kgの場合 |
| --- | --- | --- |
| 無理がない | 週0.5%以下 | 週0.6kgまで |
| 頑張りすぎ注意 | 週0.5〜1% | 週0.6〜1.2kg |
| 危険 | 週1%超 | 週1.2kg超 |

以前の「半年で20kg」は月3.3kg程度で、「頑張りすぎ注意」の領域にあたる。

境界値はそれぞれ下の区分に含める(週ちょうど0.5%は「無理がない」、週ちょうど1%は「頑張りすぎ注意」)。浮動小数点の誤差で境界がぶれないよう、割合は小数第2位(0.01%)に丸めてから比較する。

**標準ペースは月2%(週約0.46%)。** 計画より速く減っても目標ペースは上げず、その分を前倒しとして扱う。実績のペースは直近28日間の7日平均の変化率で測り(減量中だけ。窓が14日に満たない間は判定しない)、月3%(週約0.7%)までは見守る。実績のペースについて伝えるのは月3%を超えたときだけで、そのときはペースを落とすよう穏やかに伝える。

### ステージ構成(試算)

| ステージ | 体重 | 期間(月2%) | 期間(月3%) |
| --- | --- | --- | --- |
| 1 | 123.5 → 111.2kg | 約5か月 | 約3.5か月 |
| 2 | 111.2 → 100.0kg | 約5か月 | 約3.5か月 |
| 3 | 100.0 → 90.0kg | 約5か月 | 約3.5か月 |
| 4 | 90.0 → 81.0kg | 約5か月 | 約3.5か月 |
| 5 | 81.0 → 72.9kg | 約5か月 | 約3.5か月 |
| 6 | 72.9 → 67.4kg(最終目標で打ち切り) | 約4か月 | 約2.5か月 |
| 合計(維持期間込み) |  | 約3年4か月 | 約2年6か月 |

合計は、ステージ1〜5の後にそれぞれ2か月の維持期間を置くとして試算した値(最終目標の後は維持期間ではなく維持モードに入るため数えない)。ステージ1の中に「最初の5%(約6kg)」のマイルストーンを置く。

**境界値の決め方**

- 開始体重に0.9を丸めずに掛けて連鎖させ、各境界の値だけを最後に小数第1位へ丸める(111.2 / 100.0 / 90.0 / 81.0 / 72.9 / 67.4)。丸めた値で連鎖させると誤差が積み重なり、後半ほどずれるため。
- 到達判定はこの丸めた境界値で行い、7日平均も小数第1位に丸めてから比べる。画面に出る数字と判定を一致させるため。
- 境界値は計画を作った時点で確定させて保存し、計画を見直しても変えない。肥満症の治療指針では、3〜5%の減量で血圧や血糖などが改善しやすいとされる。

### 進み具合の目安と判定

目安は開始日の体重から月2%で日割り計算し、7日平均と比べて判定する。日割りは日ごとの複利で、1か月は30日固定とする(暦月だと月によって日数が違い、テストが煩雑になるため)。自分で計算しなくて済むよう、アプリが目安を表示する。

目安 = 開始体重 × 0.98^(経過日数 ÷ 30)

| 期間 | 目安 | 123.5kgの場合 |
| --- | --- | --- |
| 1週間 | 現体重の約0.5% | 約0.6kg |
| 2週間 | 現体重の約1% | 約1.2kg |
| 1か月 | 現体重の約2% | 約2.5kg |

| 判定 | 条件 |
| --- | --- |
| 計画どおり | 7日平均が目安の±0.5%以内(123.5kgなら±0.6kg) |
| 予定より早いペース | 目安より0.5%超下回る |
| ゆっくりペース | 目安より0.5%超上回る |

- ±0.5%の分母は目安の値。差がちょうど0.5%なら「計画どおり」に含める。割合は小数第2位(0.01%)に丸めてから比較する。
- 判定は色を使わず、言葉だけで伝える。
- 開始から最初の1か月(30日)は水分が抜けて大きく減りやすいため、進み具合・実績ペース・計画見直しを判定せず、「最初の1か月は、体の水分が落ち着く時期です」の方向の一言を出す。この除外は最初のステージだけで、維持期間明けの次のステージでは起点の日から判定する。
- この判定は表示用で、計画見直しの発動条件(2%以上のずれが2週間続く)とは別に扱う。
- メイン画面では数字の目安を出さず、7日平均のグラフに計画を点線で重ねるだけにする。レポートでは目安と実際の値を並べる。

### 維持期間

10%減るごとに、減らさずに保つ期間を挟む。減った体重に体と生活を慣らし、リバウンドを防ぐ。期間は固定せず、条件を満たしたら次のステージへ進む。

| 項目 | ルール |
| --- | --- |
| 最低期間 | 4週間(卒業条件の4週間と同じもの) |
| 卒業条件 | 到達日から数えて、7日平均がステージ到達時の体重±2%以内に28日連続で収まる。途中で範囲を外れたら数え直す(失敗扱いの表示はしない) |
| 最長期間 | 12週間。超えても強制的には進めず、「次のステージへ進む」「維持を続ける」をカードで提案し、ユーザーが選ぶ(計画見直しと同じ提案方式) |
| 最終目標の後 | 維持期間ではなく、終わりのない「維持モード」に入る |
| 範囲から外れたとき | 維持期間・維持モードとも、7日平均が範囲外に14日続いたら穏やかな一言を出す(上に外れた場合と下に外れた場合で文言を分ける)。85日目の提案カードと重なったらカードを優先する |
| 維持中に次の境界まで減ったとき | 「次のステージの到達として扱い、そこから維持期間を始める」「維持を続ける」を選べるようにする。次が最終ステージなら到達後は維持モード |

### 計画の見直しと通知

- **発動条件:** 7日平均が計画値から2%以上ずれた状態が2週間(14日)続いたとき。
- **伝え方:** プッシュ通知は使わない。次にアプリを開いたときのカード表示か、月半ば・月末レポートの中で伝える。
- **内容:** 変更前と変更後の到達予定日を並べ、「この計画で進める」「元の計画に戻す」を選べるようにする。採用したときは、その時点の7日平均と日付を新しい起点にしてペースと到達予定日を計算し直す。ステージの境界は変えない。
- **速すぎる場合:** 実績のペース(直近28日間の7日平均の変化率)が月3%を超えたら、少し落とすよう穏やかに伝える。
- **医師への相談:** 「危険」判定が出たときや停滞が長く続いたときは、肥満外来などへの相談も選択肢として一言添える。

## データ連携

毎日HealthPlanetで同期するだけで、自作アプリには自動でデータが届く。手入力は不要。

&#91;embedded content: データの流れ · 体重計から自作アプリまで\]

HealthPlanetは起動しないと体重計と同期しないため、毎日開く。ただしホーム画面は体重だけの表示にカスタマイズし、目標値も非表示にしてあるので、評価や体組成は目に入らない。

**運用設定**

- iOSショートカットのオートメーションで、HealthPlanetを閉じたら自作アプリを開くようにする。
- 自作アプリはHealthKitの更新をバックグラウンドで検知し、ウィジェットも更新する。
- HealthKitに他のアプリの値が混ざる場合は、HealthPlanet由来のデータを優先する。その日にHealthPlanet由来の値がないときは、他のソース(ヘルスケアへの手入力など)の値を使う。
- 体脂肪率もApple Healthには毎日入るが、自作アプリは月半ば・月末レポートまで表示しない。
- 除脂肪量は体重 × (1 − 体脂肪率)で計算する。HealthKitから読み取るのは体重と体脂肪率の2つに留める。
- 筋肉量・内臓脂肪・体内年齢はApple Healthに連携されないため、扱わない。

## 技術方針

HealthKitはiOSアプリからしか読めないため、iOSネイティブ(SwiftUI)で作り、実装はClaude Code主体で進める。

- **Macのローカルで開発する。** ビルドとシミュレーターにXcodeが必要なため、Claude CodeはMac上で動かし、`xcodebuild`でビルドとテストを回す。
- **計算ロジックはSwift Packageに切り出す。** ロードマップ作成、安全性判定、7日平均、維持期間の卒業判定は、UIとHealthKitに依存しない純粋なロジックにする。`swift test`だけでテストを回し、テスト駆動で固める。
- **プロジェクトファイルはXcodeGenで生成する。** `.pbxproj`を直接編集せず、YAMLから生成する。
- **HealthKitの受信は実機で確認する。** バックグラウンドでの受信はシミュレーターでは確認できない。
- **仕様駆動で進める。** このコンセプトシートから仕様書を作り、Claude Codeに渡して実装する。
